# T2 PR#3b: экспорт ключей, `rebuild-meta`, ротация KEK

Вторая половина T2 PR#3. Формат файла объекта — [ADR-0019](../adr/0019-object-manifest-trailer.md),
правила про то, что где хранится и когда становится невосстановимым —
[ADR-0014](../adr/0014-encryption-per-tenant.md).

## Критерии ревьюера

Список составлен из постановки ревью и служит чек-листом приёмки. Каждый пункт
либо закрыт тестом, либо помечен, где он закрывается.

### Экспорт ключей тенантов

- [ ] В экспорт попадают **только живые тенанты**. После уничтожения TEK тенант
  обязан исчезнуть из следующего экспорта — тест: создать тенант, выгрузить
  экспорт, уничтожить TEK, выгрузить снова, записи нет.
- [ ] Каждая обёртка **аутентифицирована**: AEAD под KEK с AAD тенанта. Подмена
  обёртки на чужую или перестановка «обёртка ↔ тенант» даёт ошибку. Уже есть
  `keys.tekAAD` (`"tapegw-tek-v1" ‖ tenant_id_be8`) — экспорт обязан его
  использовать, а не выдумывать свой AAD. Тест: поменять местами обёртки двух
  тенантов в файле → `rebuild-meta` отказывает.
- [ ] В экспорте указаны **дата создания и версии KEK**, чтобы `rebuild-meta`
  знал, каким KEK разворачивать. Тест: экспорт, сделанный под KEK v1, не
  читается кольцом без v1 — и это отдельная ошибка, а не «файл битый».

### `rebuild-meta`

- [ ] Основной тест: записать объекты, **включая multipart с повторно
  загруженной частью**, очистить схему `tapegw`, восстановить только из лент,
  KEK и экспорта, сравнить ETag, размеры и содержимое.
- [ ] Объекты тенанта, **которого нет в экспорте** (удалён), пропускаются с
  понятной записью в отчёте, а не роняют восстановление. Отчёт обязан отличать
  «тенант удалён» от «ключ не развернулся» и от «файл испорчен».
- [ ] **Повторный запуск идемпотентен**: по уже восстановленной схеме не дублирует
  строки и не падает.
- [ ] Список объектов берётся **из Phobos**, а не из нашей БД. Иначе тест
  проверяет чтение собственной базы, а не восстановление из архива.

### CLI ротации KEK

- [ ] Перешифровывает все TEK в БД (`RotateKEK` идемпотентен: строки на активной
  версии пропускает, прерванный прогон повторяем).
- [ ] **Старая версия KEK обязана пережить ротацию** ровно на
  `max(keys.export_retention, срок PITR-бэкапов)`: до тех пор существуют
  экспорты и бэкапы, сделанные до ротации и завернутые старым KEK. CLI обязан
  **проверять** это, а не полагаться на внимательность оператора: команда
  «забыть версию KEK» отказывает, пока не прошёл срок, и объясняет почему.

## Разбиение внутри 3b

`rebuild-meta` требует читать Phobos, а `internal/store/phobos` ещё нет. Правило 2
(`go build ./...` проходит без Phobos и без cgo) означает, что список и чтение
объектов описываются **интерфейсом**, а cgo-реализация живёт под тегом `phobos`.
Иначе тест «список берётся из Phobos» пришлось бы гонять только на стенде, и в CI
он не запускался бы вовсе.

Поэтому:

1. **`internal/archive`** — интерфейс `Archive`: `List(ctx) ([]ObjectRef, error)` и
   `Read(ctx, ref, offset, length)`. `ObjectRef` = oid + атрибуты. Фейковая
   реализация для тестов: каталог на диске, где имя файла — oid, а рядом лежит
   JSON с атрибутами.
2. **Экспорт ключей** — `internal/keys/export.go`: формат файла, запись и чтение,
   проверка AAD. CLI `tapegw-kectl export|verify`.
3. **`rebuild-meta`** — `internal/rebuild`: читает `Archive`, разворачивает
   манифест (ADR-0019), вставляет `objects` и `object_parts`, печатает отчёт.
   CLI — подкоманда `tapegw admin rebuild-meta`.
4. **Ротация KEK** — CLI поверх существующего `keys.RotateKEK` + проверка срока
   «забыть старую версию».
5. **cgo-реализация `Archive`** под тегом `phobos` — в стенде `ci-dir`, вне CI.
   Её отсутствие в CI осознанно: вся логика восстановления проверяется на фейке,
   а стенд проверяет только «Phobos отдаёт то, что мы описали интерфейсом».

## Замечание про mover

Уточнение ревьюера к ADR-0007 внесено здесь же: mover **получает обёрнутый DEK**
(это данные для атрибута, без TEK бесполезен), но никогда не получает развёрнутых
ключей и TEK.
