# ADR-0021. Протокол tapegw ↔ mover

- **Статус:** предложено (область зафиксирована, детали — отдельным PR до кода mover)
- **Дата:** 2026-11-05
- **Этап плана:** M4
- **Связано:** [ADR-0007](0007-mover-worker.md) (mover как отдельный бинарь),
  [ADR-0020](0020-tape-record-format.md) (формат записи на ленту),
  [ADR-0006](0006-libphobos-linkage.md), [ADR-0008](0008-object-medium.md),
  спайк [M0-02](../spikes/M0-02-libphobos-api.md).

## Контекст

По ADR-0007 вызовы Phobos живут в отдельном процессе `tapegw-mover`: только он
линкуется с libphobos, только он держит драйв, и падение его не утаскивает за
собой шлюз (libltfs падает во время `mt offline`, а не возвращает ошибку).

Формат того, что ложится на ленту, зафиксирован отдельно — в ADR-0020. Это
разделение сознательное: формат после первой записи меняется только перезаписью
ленты, а протокол между процессами меняется вместе с обоими бинарями и не
требует никакой миграции данных. Держать их в одном документе означало бы
либо раздувать ревью формата деталями IPC, либо требовать от протокола строгости,
которая оправдана только для неизменяемого формата.

## Решение

Этот ADR фиксирует **область** и инварианты; конкретные сообщения, коды ошибок и
транспорт определяются в дополнении к нему, до первой строки кода mover.

Что входит:

- постановка работы mover'у (архивация батча, чтение объекта при restore,
  удаление) и ответ о результате;
- как mover узнаёт, какие атрибуты положить (ADR-0020 их задаёт, mover их не
  выдумывает);
- как передаётся путь к файлу в спуле, а не его содержимое;
- как переживается падение mover'а посреди операции (правило 7: воркер
  идемпотентен, переход состояния — `UPDATE … WHERE state = <ожидаемое>`);
- как считается итог операции: возвратный код Phobos сам по себе ничего не
  значит, надо сверять `getmd` и `copy_status` (спайк M0-02).

Что **не** входит: формат файла объекта, пачки, журнала и снимка — ADR-0020.

Инварианты, которые не зависят от выбора транспорта:

1. **Mover не получает развёрнутых ключей и TEK** (ADR-0007). Обёрнутый DEK —
   да, как данные для атрибута; развёрнутые ключи — никогда.
2. **Ни одна транзакция Postgres не открыта на время вызова Phobos** (правило 13).
   mover не имеет доступа к БД вообще: состояние переходит на стороне tapegw.
3. **Вызовы слоя данных сериализованы** (ADR-0006): libphobos однопоточен,
   `phobos.max_inflight` — это число процессов-воркеров, а не горутин.
4. Протокол обязан переживать долгую операцию: батч на 200 GiB идёт минуты, и
   «соединение закрылось по таймауту» не должно означать «операция не началась».

## Последствия

Два документа вместо одного: ревью формата не отвлекается на IPC, а протокол
можно править, не поднимая вопрос о совместимости с уже записанными лентами.

## Отклонённые альтернативы

- **Один ADR на формат и протокол** — см. контекст.
- **Отложить протокол до кода mover'а** — тогда протокол напишется поверх
  существующих вызовов и повторит их один в один, то есть будет не протоколом, а
  затычкой (об этом же говорит порядок работ в M4).
