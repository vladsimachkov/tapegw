# Вертикальный срез на ci-dir

Цель: один прогон в контейнере доказывает, что архитектура работает целиком.
Лента для этого не нужна — `dir` ведёт себя как носитель, а механика ленты
добавляется потом и архитектуру не меняет.

## Что должно получиться

Один `docker`-стенд: `tapegw` + один `tapegw-mover` + Phobos (`dir`) + Postgres.
Один тенант, одна копия, бакет без версий.

```
PUT объекта  → объект принят и лежит в landing
архивация    → пачка ушла в Phobos, state=archived
вытеснение   → файл из landing удалён (ADR-0004)
RestoreObject → данные снова доступны
GET          → вернулись исходные байты (совпала sha256)
```

Проверяется e2e-тестом против этого стенда: те же байты на входе и на выходе,
`x-amz-restore` переходит в `restored`, после истечения срока — снова
`GlacierAccessDenied`.

## Что уже есть

- `store/phobos`: `Put`/`Get`/`Delete`/`Stat`/`Extents` через cgo, владелец-горутина;
- `storetest`: общий набор сценариев для `fake` и настоящего Phobos;
- `mover`: протокол, реестр буферов, mTLS, клиент и сервер; `movertest` — стенд;
- `pack`: формат пачки (запись и чтение), детерминизм;
- `migrator`: выборка батча, запечатывание до отправки, возобновление с пачки,
  владение воркера, блокировка разобранной пачки, цикл архивации с проверкой
  ожидаемой `sha256`;
- `meta`: таблицы пачек, копий, носителей, восстановлений; очереди;
- `ci-dir`: контейнер с Phobos и `dir`-библиотекой поднимается одной командой.

## Чего нет (порядок работы)

1. **`tapegw-mover` как бинарь.** Сейчас mover живёт только как библиотека и в
   тестах. Нужен `cmd/tapegw-mover`: конфиг, mTLS-сервер, один слот на драйв,
   `store/phobos` за ним. Без него нечего запускать в стенде.
2. **Подключение migrator к настоящему mover.** Цикл написан и проверен на
   `fake` и `movertest`; нужен провод до реального `store/phobos` через mover.
3. **Janitor: вытеснение.** Снять флаг в БД → `unlink` (обратный порядок,
   ADR-0004), по `online_until`. Минимум — этот один шаг; сироты и брошенные
   multipart — после среза.
4. **Recaller: минимальный `RestoreObject`.** Один вариант: прочитать с
   носителя в landing и выставить `restored` до `restored_at + days`. Никакого
   приоритета, нескольких уровней и ускорения — после.
5. **Сборка стенда и e2e.** `deploy/Containerfile.ci-dir` + compose с mover'ом,
   e2e-тест полного пути.

Пункты 1–4 — по одному PR, каждый с тестом; 5 — финальный.

## Что после среза

1a-3 (тот же набор на mhVTL и «не `sync`» по DSS), `klipper-tlc`, догонка
недостающих копий, журнал, остальной janitor, repack и учёт брошенных байт,
проверка целостности лент.

## Правило проверки для каждого PR

Вопрос один: **приближает ли это к списку выше.** Если нет и это не исправление
корректности — PR откладывается, а не идёт параллельно.
