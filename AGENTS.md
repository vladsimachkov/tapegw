# tapegw — правила для агента

Источник истины — [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Этот файл — краткая
выжимка плюс команды. При любом расхождении выигрывает `ARCHITECTURE.md`, а отступление
оформляется ADR в `docs/adr/`.

## Команды

```bash
go build ./...                 # сборка всего (без cgo, Phobos не нужен)
go test ./...                  # юнит-тесты (без cgo, без Postgres для чистых пакетов)
go test -race ./...            # проверка гонок, обязательно для изменений очередей
go vet ./...
staticcheck ./...              # требует go install honnef.co/go/tools/cmd/staticcheck@latest
gofmt -l .                     # должен печатать пусто

# Сборка с реальным Phobos (только стенд ci-dir / контейнер EL9)
go build -tags phobos ./...

# Миграции применяются при старте tapegw, отдельно запускать не нужно
```

Тесты, которым нужен Postgres, поднимают его через testcontainers и пропускаются сами,
если Docker недоступен. Такие тесты помечают себя `t.Skip`.

## Железные правила

1. **`go build ./... && go test ./...` проходят на любом Linux** без Phobos и без cgo.
   Всё, что требует Phobos, — под build tag `phobos` и в стенд `ci-dir`.
2. **Исходники Phobos и versitygw не патчатся.** Ни патчей, ни форков, ни `replace` в
   `go.mod` на свою ветку. Если без патча нельзя — сначала ADR и вопрос ревьюеру.
3. **Сначала файл на диске с `fsync`, потом commit транзакции Postgres. Никогда наоборот.**
   Любая смена состояния объекта — одна транзакция.
4. **Каждый воркер идемпотентен.** Переход состояния — `UPDATE … WHERE state = <ожидаемое>`;
   ноль затронутых строк означает «опередили», воркер молча пропускает. Для каждого
   нового шага воркера обязателен тест «упасть после шага N, перезапустить, сверить».
5. **Очереди — строки в Postgres, выборка через `SELECT … FOR UPDATE SKIP LOCKED`.**
   Никаких отдельных брокеров.
6. **Неподдерживаемые S3-операции — `NotImplemented`** через встраивание
   `backend.BackendUnsupported`, а не «молча делаем что-то».
7. **Поведение S3 берём из кода versitygw, не выдумываем.** Для обычных операций —
   posix-бэкенд, для Glacier-семантики (`x-amz-restore`, storage class, RestoreObject) —
   `backend/scoutfs/scoutfs_compat.go`.
8. **cgo изолирован** в `internal/store/phobos`. Остальной код от cgo не зависит.
   Вызовы Phobos — только в пуле `phobos.max_inflight`, `runtime.KeepAlive` для `os.File`,
   C-строки в `defer`, структуры через `pho_xfer_desc_clean`.
9. **Числа — в конфиг, не константами в коде**: таймауты, размеры батчей, watermark,
   `max_attempts`. Любое поле переопределяется переменной `TAPEGW_*`.
10. **Ошибки** через `fmt.Errorf("…: %w", err)`, **логи** через `log/slog` (JSON),
    `panic` только в `main`.
11. **Один PR — один пункт плана** из раздела «План разработки» в `ARCHITECTURE.md`.
    Миграции БД только вперёд, одна миграция на PR, уже слитые не правим.
12. **Лицензия — Apache-2.0.** Файлы, перенесённые из Phobos (в т.ч. `.proto`),
    сохраняют LGPL-заголовок.

## Версии

- Go — `1.26.0`, как `go.mod` versitygw. Ставится автоматически через `GOTOOLCHAIN`.
- versitygw зафиксирован точной версией в `go.mod`; обновление — отдельный PR с прогоном e2e.
- Phobos — релизный тег, собирается в контейнере EL9.

## Чего нет в MVP

Версионирование бакетов, Object Lock, lifecycle, S3 Select, несколько узлов, упаковка
мелких объектов, освобождение места на лентах после удалений. Всё это — отдельные ADR.
