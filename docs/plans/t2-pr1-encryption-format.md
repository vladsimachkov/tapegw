# T2 PR#1 — формат шифрования и шифрование в спуле

- **Этап:** T2 (первый из трёх PR), [ADR-0014](../adr/0014-encryption-per-tenant.md)
- **Ветка:** `t2-pr1-encryption-format`
- **Не входит:** multipart и `object_parts` (PR#2), атрибуты Phobos и `rebuild-meta`
  (PR#3), restore (M5)

## Зачем разбито на три

Формат данных на ленте после первой записи не поменять. Поэтому сначала формат и
спул: пока он не зафиксирован, multipart писать бессмысленно — он обязан шифровать
части тем же форматом.

## Формат (ADR-0014, без отступлений)

- Сегмент — **65536 байт открытого текста**. Последний — остаток.
- Каждый сегмент — отдельный `AES-256-GCM`, тег 16 байт. Шифротекст сегмента
  ровно на 16 байт длиннее.
- **Nonce (12 байт)** = `SHA-256("tapegw-seg-v1" ‖ uuid ‖ part_be4 ‖ seg_be8)[:12]`.
  В ADR nonce описан как «UUID версии + номер части + номер сегмента»; в 12 байт
  они байт-в-байт не влезают (один UUID уже 16), поэтому берётся хеш от них.
  Коллизия nonce при одном DEK означала бы катастрофу, а `SHA-256` от уникальной
  тройки — стандартный способ вывести nonce нужной длины из более длинного материала.
- **AAD** = `uuid ‖ part_be4`. Сегмент привязан к версии и части: вырезать
  сегмент из одной версии и подставить в другую — ошибка аутентичности.
- DEK уникален на версию, поэтому повтор nonce внутри одного DEK исключён
  конструктивно, а не проверкой.

Размеры: `cipher(n) = (n/65536)*65540 + (n%65536 == 0 ? 0 : (n%65536)+16)`.
Обратное преобразование нужно для Range, и оно должно быть точным — см. тесты.

## Ключи

| Ключ | Где | Обёрнут | Кто заводит |
| --- | --- | --- | --- |
| KEK | вне БД, файл 0400 / Vault | — | оператор |
| TEK | `tenants.wrapped_key` | KEK (через существующий `iam.KeyRing`) | tapegw при первой записи |
| DEK | `objects.wrapped_dek` | TEK | tapegw при PUT |

**TEK заводится лениво** (`UPDATE … SET wrapped_key = $2 WHERE id = $1 AND
wrapped_key IS NULL`, повторное чтение при гонке). Миграцией этого не сделать:
миграция KEK не знает, а выдуманный ключ читал бы данные нечитаемыми. Лень здесь
не «сэкономить», а единственный атомарный способ: `INSERT` в миграции без KEK
невозможен, а `NULL` в колонке означает «ключа ещё нет», а не «данные не
шифруются».

DEK и TEK — массивы фиксированной длины, обнуляются после использования
(`crypto.Zero`). В `Error()` и в `slog`-полях ключей нет ни в одном пути —
проверяется тестом, а не осмотром.

## Миграция 0013

`objects.wrapped_dek` → `NOT NULL` для версий **с данными**:

```sql
CHECK (is_delete_marker OR wrapped_dek IS NOT NULL)
```

Маркер удаления тела не имеет, DEK ему не нужен.

Перед `SET NOT NULL` миграция **падает**, если в таблице есть незашифрованные
строки (`wrapped_dek IS NULL AND NOT is_delete_marker`), с внятным текстом.
Пред-T2 данные после этого PR не читаются в принципе — выдумать им DEK нельзя,
а молча оставить NULL означало бы «этот объект лежит открытым», и отличить его
от нового было бы нельзя. На стенде до T2 объектов нет; если они где-то есть,
их удаляет человек, а не миграция (правило 11: миграции не уничтожают данные
молча).

## Точки интеграции

`spool.Write` — цепочка читалок (лимит → MD5 → checksum-сверители) идёт **до**
шифрования, в файл пишется шифротекст. Порядок принципиален: ETag и
`x-amz-checksum-*` считаются по открытым данным, то есть по тому, что видит
клиент (ADR-0014).

- `spool.WriteEncrypted(id, r, spec, limit, key)` — та же функция, что `Write`,
  но поток пишется через `encrypt.Writer`. `Write` остаётся: он нужен тестам
  формата и janitor-путям без ключа.
- `spool.Open` ничего не знает про шифрование — он отдаёт файл. Расшифровка на
  уровне backend: `encrypt.NewReader(f, key, plainSize)`.
- `meta.PutObject` получает `WrappedDEK`; `meta.Object` отдаёт его наружу.
- GET/HEAD: `x-amz-server-side-encryption: AES256` (как SSE-S3). Range
  пересчитывается из открытых диапазонов в шифротекстовые.

## Тесты — по шесть пунктов приёмки

| Пункт ревью | Тест |
| --- | --- |
| Range на границах сегментов | `TestReaderRanges`: смещения 65535/65536/65537, конец сегмента, пустой диапазон, диапазон через границу, весь объект, `bytes=a-`, `bytes=-k`. Сверяется с исходными байтами байт в байт |
| Порча байта даёт ошибку, а не мусор | `TestCorruptionDetected`: портится байт в середине шифротекста, в теге, в первом и последнем сегменте → `ErrCorruptedSegment`, прочитанное не отдаётся |
| Ключ тенанта уничтожен | `TestTenantKeyDestroyed`: `wrapped_key = NULL` → GET и PutObject дают ошибку, а не молча шифруют новым ключом |
| После смены KEK всё читается | `TestKEKRotation`: записать, перевернуть KEK (новая версия в keyring), прочитать — данные те же; `kek_version` в строке тенанта обновился |
| DEK в атрибутах Phobos | **PR#3** — здесь только хелпер упаковки атрибута и тест, что атрибут не содержит ключ в открытом виде |
| Ключи не в логах и ошибках | `TestKeysNotInErrors`: собрать все ошибки путей шифрования и все `slog`-поля, искать байты DEK/TEK/KEK |

Плюс обязательные: `TestWriterReaderRoundTrip` (размеры 0, 1, 65535, 65536,
65537, 2×65536+7), `TestNonceUniquePerVersion` (одинаковый plaintext в двух
версиях даёт разный шифротекст), `TestAADBindsSegment`, `TestMigration…`
(0013 на таблице **с данными**, по правилу 11), мутации.

## Мутации, которые обязаны быть пойманы

1. Range читает сегменты без смещения внутри сегмента → `TestReaderRanges`.
2. Тег не проверяется (чтение «как есть») → `TestCorruptionDetected`.
3. ETag считается по шифротексту → e2e на ETag и `TestPutObjectChecksum`.
4. `wrapped_dek` не пишется → NOT NULL из миграции 0013.
