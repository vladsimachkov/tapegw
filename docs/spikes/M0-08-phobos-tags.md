# M0-08: теги Phobos в записи — жёсткий фильтр или предпочтение

- **Статус:** закрыт
- **Дата:** 2026-11-03
- **Phobos:** 3.4.1 (сборка из исходников, тег `3.4.1`), стенд `tapegw-vm` (AlmaLinux 9.8, mhVTL)
- **Вопрос из плана:** является ли тег в `phobos_put` (`put.tags`) **жёстким фильтром**
  — лента без тега пула не берётся никогда — или **предпочтением**. Если предпочтение,
  физического разделения тенантов теги не дадут, и ADR-0013 (пулы) надо пересматривать.

## Краткий ответ

**Жёсткий фильтр, семантика И** — но изоляция односторонняя: тег ограничивает выбор
при **запрошенном** теге и никак не защищает помеченную ленту от записи **без** тега.

Поэтому пулы через теги жизнеспособны, но только при одном дополнительном правиле:
**tapegw обязан тегировать каждую запись, включая общий пул.** Необозначенной записи
не должно существовать ни в одном пути. Это требование в ADR-0013, без него выделенный
пул не выделен.

## Что проверялось

Две ленты, обе загружены в драйвы: `TST001` (свободно 974 MiB) и `TST002`
(свободно 1.99 GiB). Запись шла так, как её будет делать migrator: `-f tape -L vtllib
-l raid1 -P repl_count=1`.

| # | Опыт | Ожидали при жёстком фильтре | Результат |
| --- | --- | --- | --- |
| A | `put -T poolB`, тегов `poolB` нет ни на одной ленте | отказ | **ENOSPC**, rc=28; объекта в каталоге нет |
| B | `put -T poolA`, тег только на `TST001` | уйдёт на `TST001` | ушёл на `TST001` |
| C | `put` без тега, `TST001` помечен | — | ушёл на `TST001`, тег не помешал |
| D | `put` без тега, **обе** ленты помечены разными пулами (`poolA`/`poolB`) | — | **успех**, лёг на `TST001` (чужой пул) |
| E | `put -T poolA,poolB` — ни одна лента не имеет обоих тегов | отказ | **ENOSPC**, rc=28 |
| F | `put -T poolA --no-split`, файл 1.287 GiB > остатка `TST001`, но < остатка `TST002` | отказ, а не перелив на чужую ленту | **ENOSPC**, rc=28; на `TST002` ничего не попало |

После всех опытов: `phobos extent list -s orphan` — пусто; отказавшие объекты
(`poolB`, `poolB2`, `both`, `bigA`) в каталоге отсутствуют. Откат чистый, как и в
[M0-07](M0-07-mhvtl-ltfs.md) на обычном ENOSPC.

Справка CLI формулирует семантику прямо: `-T TAGS — only use media that contain all
these tags`. Опыт E подтверждает, что «all» — это И, а не «любой из».

## Что это значит для пулов (ADR-0013)

**Хорошая новость:** T2 стоит. Требование «батч пишется целиком в свой пул» Phobos
обеспечивает: опыт F показывает, что даже под `no_split` он не перельёт на ленту чужого
пула, а честно вернёт ENOSPC. Опыт A — что опечатка в теге не приведёт к записи не туда.

**Плохая новость, и она важнее:** опыт D — изоляция односторонняя. Помеченная лента
ничем не защищена от записи без тега. Если tapegw где-то напишет без тега, объект
клиента из общего пула ляжет на ленту выделенного пула, и «отдать клиенту его ленты»
(пункт ADR-0013) станет неправдой: на них окажется чужой объект.

Отсюда обязательные требования:

1. **Каждая запись несёт тег пула.** Общий пул — не «без тега», а со своим тегом
   (например, `pool:shared`). Пул объекту фиксируется на PUT (ADR-0008 по духу),
   значит тег всегда известен, и «некуда поставить тег» в коде не бывает.
2. **Каждая лента вводится в Phobos с тегом ровно одного пула.** Ленты без тега —
   конфигурационная ошибка; её надо находить на старте migrator, а не в рантайме.
3. **Проверка на старте migrator:** ни одной ленты без тега пула и ни одной с тегом
   неизвестного пула. Иначе пункт 1 легко потерять при первой же доработке.

## Побочный вывод: ENOSPC двусмысленен, и это ломает страховку из M4

Отказ «нет ленты с таким тегом» и отказ «лента кончилась» для Phobos **выглядят
одинаково**: `ENOSPC`, rc=28. Отличить их по коду нельзя.

Это прямо задевает страховку из M4 («при ENOSPC делим батч пополам и повторяем, вплоть
до одного объекта, дальше алерт «нужны новые ленты»»). При неверном теге она будет
бесполезно крутить цикл и в конце выдаст «нужны новые ленты», хотя лент полно — просто
не тех. Диагностика уйдёт не туда.

Что добавить в M4: перед делением батча уточнять, есть ли вообще свободное место у лент
**этого пула** — `phobos tape list -T <tag> -o name,stats.phys_spc_free` (для API —
соответствующий запрос). Если у пула места нет — это «пул исчерпан», алерт по пулу;
если место есть, но батч не влезает — тогда делить.

## Мелочи, которые пригодятся

- Поля вывода `phobos tape list`: `name`, `fs.status`, `adm_status`, `family`,
  `library`, `stats.phys_spc_free`, `stats.phys_spc_used`, `stats.nb_obj`,
  `stats.nb_errors`, `stats.nb_load`, `stats.last_load`.
- **`tags` в списке выводимых полей нет** — тег нельзя прочитать у ленты напрямую,
  только отфильтровать `-T`. Для аудита («какие теги вообще развешаны») придётся
  перебирать кандидаты. Учитывать в админ-API и CLI.
- `stats.nb_obj` после `phobos delete` не уменьшается (после опытов осталось 10 вместо
  ожидаемых 7): удаления не освобождают ленту до repack. Совпадает со строкой риска
  «Удаления не освобождают ленту» в `ARCHITECTURE.md` — метрика «доля удалённых байт»
  по `nb_obj` не считается, нужны другие данные.

## Итог для плана

Ответ на вопрос плана — **жёсткий фильтр**, ADR-0013 в силе и не требует пересмотра.
Но в ADR-0013 добавляются три требования про обязательное тегирование (см. выше), а в
M4 — уточнение про различение «пул исчерпан» и «батч не влез».
